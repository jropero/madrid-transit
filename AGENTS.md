# AGENTS.md

Madrid Cercanías (Renfe), CRTM interurban bus and light rail (Metro Ligero ML1-ML3, Tranvía de Parla ML4) departures. React 19 + TypeScript on Vite+ (`vp`), installable PWA, Windows Phone "Metro" look. Sibling of basel-transit. Static timetable comes from Renfe's open GTFS (baked into `public/data/` at build time), live delays, cancellations and alerts from Renfe's GTFS-Realtime JSON. Buses (NAP feed 1361) and light rail use the timetable plus CRTM stop times (an **undocumented** website endpoint that may change or break; the timetable is the fallback). For setup and deployment, see [README.md](README.md).

## Commands

- `vp dev`: dev server at http://localhost:5173/m/ (base is `/m/`)
- `pnpm data`: runs `scripts/timetable.mjs` (downloads the GTFS zips into `.cache/`, rebuilds `public/data/`; cached zips younger than 24 h are reused). `vp run build` runs it first, then `tsc` and the production build. Run the build after every change; there is no test runner.
- `vp lint` (`pnpm lint`): Oxlint with type-aware checks plus SonarJS rules (cognitive complexity max 6, no nested ternaries). Rules live in the `lint` block of `vite.config.ts`. Fix findings rather than disabling rules; if a rule really doesn't fit, turn it off in the config with a one-line reason, not inline.
- `vp fmt` / `vp fmt --check`: Oxfmt, single quotes, 96 columns. `pnpm lint:css`: stylelint on `src/index.css`. `pnpm typecheck`: `tsc --noEmit`.
- Pre-commit hook (`.husky/pre-commit`) runs `vp staged`. Needs Node >= 22.22.
- Package manager: pnpm (`vp add`, `vp remove`). No new runtime dependencies for things a few lines can do.

## Layout

- `scripts/timetable.mjs`: plain Node, no dependencies. One step per feed (`buildRenfe`, `buildCrtm(BUS | ML)`) sharing the streaming CSV reader: system `unzip -p` + `readline`, never extracting files (`shapes.txt` is 196 MB, never touched). Renfe keeps Madrid routes (`route_id` starting `10T`). Writes `public/data/` (gitignored): `stops.json` (all stops, lazy: search and near me only; `k: 'r' | 'm' | 't' | 'b' | 'e'`, bus and tram stops add `code` and `desc` = street), `stops-renfe.json` (Renfe stops only, always loaded: destination names, ♿), `routes.json` (Renfe, bus and light rail; bus/tram routes add `name`, tram routes `tram: true`), `days.json` (Renfe: `{from,to,days:{yyyymmdd:[serviceId]}}`), `stop/<id>.json`, `route/<routeId>.json`. **Every GTFS field is space-padded: trim all values.** The zips are untrusted data: parse them, never execute them.
- Renfe stop file: `{r,d,o,s,a}`: route ids, destination stop ids, origin stop ids, departure rows per service id `s[serviceId] = [secs, tripId minus service prefix, r index, d index, pattern index, o index]`, and terminus arrivals `a[serviceId] = [arrSecs, tripSuffix, r index, o index, pattern index]` (trips whose LAST stop is this one; `arrSecs` = GTFS `arrival_time` at that stop, falling back to `departure_time`, may exceed 24h; sorted; the pattern index is the trip's pattern in `route/<routeId>.json`). Every file has `o` (empty if unused) and `a` (`{}` if none); terminus-only stops carry their `a` rows. Optional `ld: { c, x, a }` (Media/Larga Distancia): `c` = bus-format calendars `[weekdayMask, startYmd, endYmd, added[], removed[]]`, `x` = departure rows `[secs, c index, r index, d index, pattern index, full tripId, o index]` sorted by secs, `a` = terminus arrivals `[arrSecs, c index, r index, o index, pattern index, full tripId]` sorted by arrSecs; r/d/o index into the same file's `r` / `d` / `o`. LD-only stops get `{r, d, o, s: {}, a: {}, ld}`.
- Renfe LD feed (`buildLd`): `https://ssl.renfe.com/gtransit/Fichero_AV_LD/google_transit.zip` (700 KB, no key, `.cache/ld.zip`, 24 h; a failure without a cache only warns). All products (Regional, Intercity, AVE, AVLO, AVANT, AVANT EXP, AVE Euromed). Only trips calling at a Cercanías Madrid stop are kept, plus `LD_HUBS` (60000 Puerta de Atocha, which no train shares with a Cercanías stop). Stop ids are shared with Cercanías; every stop a kept trip touches joins the Renfe stop list. Routes in `routes.json` carry `ld: true`, `line` (tile label: AVE, AVLO, AVANT, Euromed, IC, MD), `name` (original product), colours from `LD_PRODUCTS`. One `service_id` per trip, with `calendar.txt` + `calendar_dates.txt` (calendar code shared with buses). Trip ids match realtime exactly; live delays come from `rt.php?f=trip_updates_LD`. Patterns go to `route/<id>.json` and `stop-lines.json` like the rest.
- Ouigo feed (`buildOuigo`, after `buildLd`; timetable only, no realtime): NAP dataset 1766, `GET https://nap.transportes.gob.es/api/Fichero/download/1766` with header `ApiKey: $NAP_TOKEN` (same `napToken` / `ensureFeed` path as the NAP bus fallback; `.cache/ouigo.zip`, 24 h). No token or any failure: warn and build without Ouigo (`Ouigo: skipped`), never fail. Ouigo uses its own stop ids, each mapped to an existing Renfe stop (`nearestRenfe`: within 600 m, the same folded name wins over the nearest; the build report prints `ouigo name -> renfe id name (m)`); an unmapped one is added as `ouigo_<id>` (`k: 'r'`). Routes `ouigo_<route_id>` in `routes.json` (`line: 'OUIGO'`, `ld: true`, `op: 'ouigo'`, pink tile `#E6007E`); trip ids `ouigo:<trip_id>` (never match Renfe realtime). Only trips calling at a Cercanías Madrid stop or `LD_HUBS` are kept. Rows go into the same per-stop `ld: { c, x, a }` as Renfe LD (`mergeLdFiles`), patterns into `route/ouigo_*.json` and `stop-lines.json`. Calendars come from `busCalendars` (`calendar.txt` and `calendar_dates.txt` are each optional via `optionalRows`). Client: `dedupeLd` keys include the operator (`isOuigo`), so Renfe and Ouigo rows never merge; `sourceOf` and the follow view say `Ouigo: solo horario`. Licence: NAP (credited as MITRAMS).
- Route file `route/<routeId>.json`: `{p: [[[stopId, offsetSecs], ...], ...]}`, unique stop patterns per route (offset from the first stop); `days.json` also has `updated` (Renfe zip date, yyyymmdd). Built by `makePatterns` / `patternOf` (Renfe, bus and tram from `byTrip`; Metro and EMT through `streamPatterns`, which streams `stop_times.txt` without keeping it). Metro stations with the same normalised name within 300 m are merged (`mergeMetro`, lowest code kept, dropped ids mapped in patterns). Client: `NextStops.tsx` (tap a line group), `pickPattern` / `nextStops` in `src/gtfs.ts`; live rows without a pattern index pick the pattern containing the stop whose last stop matches the destination, else the longest.
- Bus stop file: `{kind:'bus', r, h, c, d, t?}`: route ids, headsigns, deduplicated calendars `c[i] = [weekdayMask (bit 0 = Sunday), startYmd, endYmd, added[], removed[]]` (inlined per stop so the client never needs the 5.7k-service table), rows `d = [secs, c index, r index, h index, pattern index]` sorted by secs (may exceed 24h). The client tells the kinds apart with `isBus`. `t: 1` (`markTermini`, kept by `mergeBusFiles`) = at least one trip of the feed ends at this stop (a terminus; a stop that is only a terminus gets no file): the client then shows the salidas/llegadas switch. Bus llegadas board: `fetchCrtm(id, true)` (`type=2`, trips that END here; memo and offline keys `crtm:<code>:arr`; prefetch and health check stay departures), `useCrtm` keys its rows by stop + mode, `arrivalRows` (`src/gtfs.ts`) sets each row's `dest` to the origin (CRTM's `destination` text, kept as `route`, before the first `-`, `arrivalOrigin`; `destinationStop` is the terminus itself), and `arrivalsAt` (`src/App.tsx`) builds the board with `mergeCrtm([], rows, …)` (CRTM rows only, no timetable arrivals; seconds = live, whole minute = planned), grouped by line + origin like Renfe arrivals.
- Towns: `town` on every stop in `stops.json` / `stops-renfe.json` (empty when unknown). Source: CRTM open data (datos.crtm.es) ArcGIS layer `M8_Red` (`CODIGOESTACION` = GTFS `stop_code`, province + municipality = INE code), names from `scripts/municipios.json` (Wikidata, INE code to name). Cached in `.cache/crtm-stops.json` for 7 days; failure never fails the build. Renfe stations use the nearest bus stop's town within 1,500 m.
- Light rail feed: public ArcGIS item `https://www.arcgis.com/sharing/rest/content/items/aaed26cc0ff64b0c947ac0bc3e033196/data` (`google_transit_M10.zip`, 417 KB, no key, cached 24 h in `.cache/ml.zip`; licence https://www.crtm.es/licencia-de-uso). Same GTFS shape as buses, so stop files are `kind: 'bus'`; stop ids `par_10_<n>`, routes `10__ML1___`..`ML4`. Towns from layer `M10_Red` (`.cache/crtm-m10.json`); its short `stop_code`s collide with bus codes, so each feed is joined only to its own layer. The CSVs start with a BOM (stripped by the reader).
- Bus feed: public ArcGIS item `885399f83408473c8d815e40c5e702b7` ("GTFS Red de Autobuses Interurbanos", 73 MB, no key, same file as NAP 1361). Fallback only when that fails and a token exists: `GET https://nap.transportes.gob.es/api/Fichero/download/1361` with header `ApiKey: $NAP_TOKEN` (query `?token=` gives 401); token from the environment or `.env`, only read when needed. Neither works and no fresh `.cache/bus.zip`: warn and build without buses (never fail).
- Town buses: public ArcGIS item `357e63c2904f43aeb5d8a267a64346d8` (CRTM "Autobuses Urbanos", no key). Same GTFS shape as the interurban feed; routes are marked `urban` in `routes.json` and their stops are merged into the same per-stop files (`kind: 'bus'`).
- Metro de Madrid: ArcGIS item `5c7f2951962540d69ffe8f640d94c246` ("GTFS Red de Metro", `.cache/metro.zip`; calendar is stale, so only stations, lines and colours are read). `stops.json` gets stations (`location_type 0`, ids `par_4_<n>`, `k: 'm'`, `code`, `desc`, `town` from layer `M4_Red`, `wa` from `wheelchair_boarding`); `routes.json` keys `4__<n>___` with `metro: true`. No per-stop files: live only through `fetchCrtm` (`4_<n>`, 30 s). Light rail `wa` also comes from the feed.
- `src/gtfs.ts`: shared logic. `madridTime` (Europe/Madrid, DST-safe), `scheduled` (Renfe: today's + yesterday's services; buses: `busScheduled` with `busActive` calendar logic, removed dates win over added over weekly pattern; next 2 h), `applyRealtime`, `parseAlerts`, stop search (accent-insensitive), `nearStops`, saved stops, formatting. Put new shared logic here.
- `src/data.ts`: fetches the local timetable files (memoised) and the live feeds through `rt.php` (last copy cached for offline; `fetchCrtm` also memoises 30 s per stop). **Stale cutoff**: a live copy (rt.php stale copy via `X-Data-Age`, or the offline copy) older than `LIVE_MAX_AGE_MS` (30 min, `src/gtfs.ts`, `isLiveStale`) is dropped for times, delays and positions: `fetchFeed` returns the feed's empty value with `stale: true` (alerts have no empty value, so they stay) and the status reads `CRTM: últimos datos de las HH:MM · horario` (`staleText`; Metro/EMT: `· sin datos en vivo`). `FeedError` keeps the failing body (first 2048 chars), `url` and time; `fetchWhy(url)` asks rt.php `&why=1`. `src/StatusNote.tsx` is the `.status-note` button whose panel shows provider, HTTP status, last attempt and the response body as plain text (client-held body first, e.g. dev, else `why=1`).
- Settings "paradas guardadas" (`SavedOrder` in `src/Settings.tsx`, first section): subir / bajar buttons per saved stop reorder them through the pure `moveSaved` (`src/gtfs.ts`, with self-check) and `updateStops` in `App`; the pivot row follows, focus stays on the moved stop's button, an `aria-live` note says the new position. Settings gets `stops` / `onStops` as props.
- Settings "estado de las fuentes" (`SourceHealth` in `src/Settings.tsx`): the "comprobar" button probes Renfe `trip_updates`, CRTM for every saved `par_8_`/`par_10_`/`par_4_` stop (max 6; none saved: `8_17480` Moncloa) and EMT for saved `emt_` stops (max 3), in parallel through rt.php (`probeFeed` in `src/data.ts`: plain fetch, `cache: 'no-store'`, no memo or offline copy, never throws). `healthChecks` / `crtmCounts` / `healthLine` (`src/gtfs.ts`) turn each answer into one line: `bien · 0,6 s · copia de hace 12 s · 15 próximas (9 en vivo, 6 horario)`, `sin horas en las próximas 2 h`, `respuesta vacía`, `error HTTP …`, `sin respuesta en 65 s`, `sin conexión` (levels ok / warn `--late` / bad `--bad`).
- `src/storage.ts`: `loadJson` / `saveJson` with oldest-first eviction of cache entries.
- `src/App.tsx`: departures pane (saved-stop pivot, search, near me, lines grouped by line + destination, alerts, 30 s refresh of Renfe data, 30 s of CRTM for bus/tram/Metro stops; Renfe stations get a salidas/llegadas switch: arrivals = `renfeArrivals`, grouped by line + origin, `dedupeLd(…, true)`; every stop with departures gets a por línea / por hora switch (`SortSwitch`, `madrid-transit:sort` = `'line' | 'time'`, `parseSort`): por hora = `TimeRows`, one single-departure `LineGroup` per departure in expected-time order, all modes and media/larga distancia mixed, `timeOrdered` caps it at `TIME_ROWS_MAX` 30; `openLine` only applies to por línea) and the swipe pivot (`VIEWS`, endless in both directions: `usePivot` in `src/pivot.ts`; pointer-driven, not native scroll: previous / active / next panes sit at slots -1/0/1 via `translateX(calc(slot*100% + var(--drag)))`, the rest `visibility: hidden`, all stay mounted; the gesture locks horizontal after 10 px, drag starts on inputs or `[data-no-swipe]` are ignored, release by 25% width or 0.4 px/ms, 250 ms `.settling` transition; `goTo` slides to a neighbour or jumps with the `.turn` entrance; horizontal wheel steps once per 500 ms; `syncHistory` runs once per view change). `usePrefetchLive`: 1.5 s after start, and on coming back to the foreground or online, fetches the live times of the saved stops (`prefetchTargets` in `src/gtfs.ts`: CRTM `par_8_`/`par_10_`/`par_4_` max 6, EMT max 3, the health-check caps; `prefetchLive` in `src/data.ts`, all in parallel, failures ignored) so switching stops is served from the 30 s memo; CRTM only takes one stop per request (`codStop` lists give 502). `src/Alerts.tsx`, `src/AppBar.tsx`, `src/RefreshBar.tsx`, `src/Settings.tsx`, `src/accent.ts`, `src/motion.ts`, `src/icons.tsx` (vendored Fluent icons, don't add the package) come from basel-transit.
- Line scan (pivot "escáner", `VIEWS = departures | line | settings`; `src/LineScan.tsx`: `useLineScan`, owned by `App`, and `LineTab`): for bus / light rail stops (`isBus(file)`) with no live CRTM times, walks back along a chosen line + direction to the nearest earlier stop with a live bus and projects its time onto the selected stop. Started from the tab (pick a `lineOptions` pair, "escanear") or from salidas: an expanded bus / light-rail `LineGroup` with no live departure shows "estima tiempo" above its stop list (`EstimateButton`, `EstimateCtx` provided by `App`, `optionFor` picks the route + headsign option), which starts the scan and shows the escáner tab; "detener" cancels and clears the target and the estimate); the tab follows `nav.stop` and the scan resets when it changes. Pure logic in `src/gtfs.ts` (self-checked): `lineOptions` (route + headsign, most common pattern), `scanOrder` (every earlier stop, nearest first, back to the first stop), `liveMatches` (route matches, not `scheduled`, `dest` = headsign, or the stop has one direction: `singleHead`), `projectRows` (`when + (offHere - offU)`; rows get `estimated: true`, `from`, `dest` = headsign, `pi`), `estimateRows` (drops projected rows for a route + headsign the stop's own in-window non-scheduled rows cover). Running: `probeStop` = `fetchCrtm(U)` + `loadStopDeps(U)` + `directCrtm`, batches of 3 (never more than 3 in flight), the first batch with a match ends the pass (nearest wins), a generation counter drops late answers; after a hit the next pass is due 30 s after the last one ended (`nextAt`; a hidden page waits and runs on becoming visible; "comprobar ahora" = `refresh`, "volver a escanear" after a pass without a bus); a hit never switches the pivot (the estimate waits on salidas). The tab shows `ScanPanel` (`scanInfo`, self-checked: phase line announced via `aria-live`, a progress bar during a pass, the stops in flight and "esperando al CRTM N s" past 3 s, "comprobado hace N s" and the countdown "siguiente comprobación en N s" or "en pausa…"; 1 s tick only while a target is set), whether the stop itself is live for the line (`useOwnLive`, memoised fetch) and the stop list in scan order: this stop first, then the earlier stops nearest first, each shown once its check starts (`revealed`, self-checked), then "N paradas anteriores sin comprobar"; stops after this one are not listed. Salidas: `Departures` gets the projected rows as a prop, `withEstimates` (`src/App.tsx`) appends them to the stop's CRTM rows before `mergeCrtm` (departures only, not the llegadas board); `crtmDeparture` turns them into `estimated: true, live: false` (never "en vivo", so `freshText` ignores them) and `DepartureRow` shows the `estimado` tag (`.tag.estimated`: solid accent outline at full strength, between live and the dimmed, dashed "no confirmado").
- Alerts tab (`src/AlertsTab.tsx`, pivot `VIEWS = departures | line | alerts | settings`, labels salidas · escáner · alertas · ajustes; `App` passes `nav.stop`, `active`, `routes`): all alerts for the selected stop plus every stop (any kind) within `AREA_RADIUS` 500 m (`stopsWithin` in `src/gtfs.ts`, from `loadAllStops()`), or around the user ("cerca de mí", `locate()`, `nearFailure` from `src/data.ts`). One section per entry of `SOURCES` (`{key, label, kinds, load}`; section shown only if the area has stops of those kinds; adding a source = one entry): Renfe (`fetchAlerts` + `parseAlerts`, narrowed with `alertsFor` to the routes of the area's Renfe stops from `loadStopDeps(id).r`, line tiles from `routes.json`), EMT (`fetchEmt` + `parseEmtIncidents` for the 6 nearest EMT stops, 3 requests in flight via `pool`, merged by id/text with the stops seen at: `mergeIncidents`), CRTM (mode-wide "Avisos" notices, `loadCrtm`: one group per mode present in the area, `b` interurbanos / `t` metro ligero / `m` metro, each with its own "sin avisos" or error + `StatusNote`; muted line "avisos generales del CRTM para toda la red"; `parseAvisos` in `src/avisos.ts` via DOMParser, date from the h3 id, `fetchAvisos` memo 10 min). Alerts are shown expanded; dismissals are ignored. Loads when active and when the centre changes, then every 60 s while visible (relies on the fetch memos, no storage).
- `src/nav.ts` (`useStopNav`): stop navigation history. A jump (line stop list, ⓘ connection, search "ver") pushes `{view:'departures', stop, trail, openLine?}` (the entry left gets `openLine`); picking a saved stop only `replaceState`s; `popstate` re-selects the entry's stop and re-expands its line; `trail` (stops from the exploration start to here, restored from `history.state` on reload) drives the breadcrumb row (`Trail.tsx`, earlier crumbs call `history.go(-n)`) and the app bar's first action "volver" (`history.back()`) while it has 2+ stops; a saved-stop pick or reaching the start clears it. On a fresh load the stack is `{guard:true}` + the app entry; a popstate landing on the guard shows the "Vuelve atrás otra vez para salir" toast (2 s) and re-pushes the app entry, a second back within 2 s calls `history.back()` and exits. The settings pivot entry sits on top of the app entry.
- `public/rt.php`: whitelist proxy (no CORS upstream): `?f=trip_updates|alerts` to `https://gtfsrt.renfe.com/<f>.json` (15 s cache) and `?f=crtm&stop=<4|6|8|10>_<digits>` (validated with `^(4|6|8|10)_\d{1,6}\z`, else 400), optional `&type=2` (exactly that, else 400) = trips that END at the stop, upstream `type=2`; its cache, lock, `neg-`, `uerr-` and log names carry `-arr`, budget and IP limit are shared to CRTM's `GetStopsTimes.php` (30 s cache per stop, only valid JSON cached; an answer with no row in the next 2 h (`crtm_no_times`: `"times": {}` at tram stop 10_53, or only far-future rows at bus stop 07827; CRTM glitches, the times come back within a minute) is never cached: a cached copy with rows under `STALE_MAX` 120 s old is served instead, else the empty answer goes out uncached (`no-store`, `X-Data-Age: 0`); `take_empty` / `serve_uncached`, logged as `empty`). In dev, the Vite proxy in `vite.config.ts` rewrites `/m/rt.php?...` to the same URLs (`type=2` passed through), so client code is identical. Stale-while-revalidate: a copy past its TTL but under 120 s old is served at once and refreshed after the response is flushed (`fastcgi_finish_request` or `litespeed_finish_request`, `finish_request_fn`; per-stop lock file, 12 s upstream timeout; otherwise a synchronous fetch with 8 s; CRTM always waits `CRTM_TIMEOUT` 60 s, PHP run limit raised to match, client `CRTM_TIMEOUT_MS` 65 s, other feeds 12 s); every answer has `X-Data-Age` (seconds since fetched). The failure record `uerr-<cache>` is JSON `{code, kind, at, body}` (body = first 2048 bytes of the upstream answer); `&why=1` on any valid feed request (after validation, allow-list and the per-IP limit) returns it as `application/json` (`{}` if none, `no-store`) and never calls upstream or touches budgets. Failed upstream calls (curl/network error, timeout, non-2xx, body not JSON) are remembered per cache file (`uerr-<cache name>` in `state_dir()`, cleared by the next success) and sent as `X-Upstream-Error: <http code, 0 = none> <timeout|network|http|invalid|html>` with a stale copy and on 502/503 answers (`invalid` = 2xx body not JSON, `html` = it starts with `<`); `fetchFeed` (`src/data.ts`) returns it as `upstream`, throws `FeedError` carrying the same, and in dev (no rt.php) derives it from the status/body itself; `upstreamText` (`src/gtfs.ts`) renders the muted `status-note` line under the stop status (`CRTM: HTTP 200 · respuesta no válida (HTML)`), hidden when healthy. Debug log (`DEBUG_LOG`, CRTM only): every CRTM call and every skipped one is appended to `log-crtm-<stop>.jsonl` in `state_dir()` as `{at, time, ms, status, kind, bg, sapi, bytes, body}` (`sapi` = `PHP_SAPI` + the finish-request call in use, to see whether background refreshes can run) (`kind` = `ok`, `empty`, a failure kind, `neg` or `budget`; body up to `LOG_BODY_MAX` 64 KB; past `LOG_MAX` 1 MB the file rotates to `.1`); `&log=1` on a CRTM request returns both generations as a JSON array (oldest first, `no-store`, no upstream call). Set `DEBUG_LOG = false` once there are other users.
- CRTM notices: `rt.php?f=crtm_avisos&m=<interurbanos|metro|metro-ligero>` (`m` validated exactly, else `400 bad mode`) fetches `https://www.crtm.es/comunicacion/actualidad-del-servicio/avisos/avisos-<m>/` (sent with `User-Agent: madrid-transit/1.0`: without one crtm.es answers 403; plain HTML, no key), keeps only the `contAvisosInfo` block (`avisos_block`, max 64 KB) and caches `{html, at}` 600 s (`avisos_refresh` + `serve_swr`; no block, non-2xx or network error: `up_fail` + `neg_set`, stale copy served, else 502; `why=1` works). Dev: the `avisosDev` plugin in `vite.config.ts` (before the proxy) does the same with `scripts/avisos-block.mjs` (keep in step with `avisos_block`).
- Abuse limits in `rt.php`: `public/rt-stops.php` is **generated** by `scripts/timetable.mjs` (gitignored; `<?php return ['emt' => ['72' => 1, ...], 'crtm' => ['8_16578' => 1, ...]];`: EMT numbers, CRTM `8_`/`10_`/`4_` codes and `6_<emt number>`); a well-formed but unknown `stop` is `404 unknown stop` with no upstream call (file missing: format check only). Upstream budget per minute (`EMT_BUDGET` / `CRTM_BUDGET`, 30 each; over it: stale cache or `503 busy`), negative cache `NEG_TTL` 120 s per failed stop, per-client `IP_LIMIT` 120 req/min (`429`; only a SHA-256 of IP+minute is stored). Raise limits by editing the constants at the top of `rt.php`. All state (caches, EMT token, counters, markers) is in `state_dir()`: `__DIR__/../../cache/madrid-transit` (outside `public_html`, mode 0700; system temp dir only if it can't be created). The deploy workflow lints the PHP and smoke-tests rejected requests before uploading.
- Follow a train (Renfe only; buses, light rail, Metro and EMT keep `PlainStops`): `rt.php?f=vehicle_positions|vehicle_positions_LD` proxies Renfe's GTFS-RT vehicle positions (same upstream, 15 s cache and whitelist as trip_updates; dev proxy in `vite.config.ts` too). `fetchPositions(ld)` (`src/data.ts`, memoised 15 s, last copy cached for offline) slims it to tripId, stopId, status, timestamp; `slimTrips` now keeps `stopTimeUpdate` as stopId + arrival/departure delay/time. In an expanded Renfe group `LineGroup` shows `TrainPicker` (one `aria-pressed` button per departure, first by default) and `FollowTrain` (`NextStops.tsx`) lists the whole trip of the picked one: earlier stops folded ("N paradas anteriores"), a position row (`trainProgress`: STOPPED_AT 'at', INCOMING_AT 'arriving', IN_TRANSIT_TO 'between'), passed stops dimmed, expected time per stop (`plannedTimes` + `stopDelays` per-stop delay, else the trip delay, else planned; all pure in `src/gtfs.ts`). Positions and the trip update refresh every 30 s while the group is open and the page visible (`useLive`); status `en vivo · HH:MM` / `sin posición en vivo` / `sin conexión`. LD trips use the `_LD` feeds.
- Weather (stop title): `WeatherMark` (`src/Weather.tsx`, at the far right of `.title-row`, vertically centred on the (possibly wrapped) title, the flex row around the title `h2`; its right edge lines up with the minutes column of the departure rows) shows a Fluent icon + rounded temperature (`.weather`, `role="img"` with a Spanish `aria-label`, e.g. "Nublado, 14 °C") for the selected stop's `lat`/`lon` (no coordinates: nothing). ## Data notes

- Renfe: feed covers about one month, one `service_id` per date, no `calendar_dates`. `days.json.to` drives the "timetable ends DD.MM — redeploy" warning.
- `trip_headsign` is blank: the destination is the trip's last stop. Realtime `tripUpdate.trip.tripId` matches GTFS `trip_id`; the delay is trip-level seconds. Alerts name routes (`10T0005C2`); only `10T` ones are shown, in Spanish as supplied.
- Buses: ids `par_8_17480` (Moncloa interchange), routes `8__421___`, headsigns = `trip_short_name` minus the line number (`shortNameDest`: "461 PARLA" -> PARLA; `trip_headsign` is the last stop name, kept only as fallback; light rail keeps `trip_headsign`; `fixShortHeads` replaces short names that name the origin, per route + direction + last stop, only when the group's main destination shares a word with the last stop's name, e.g. 464 "PARLA (Por Palomeque…)" ending at Plaza Elíptica; the build prints how many), uppercase (shown lowercase by CSS), ~6.6k served stops, 354 routes. `wheelchair_accessible` is 0 everywhere, so no ♿ for buses. Live delays and alerts apply to Renfe stops only. Bus/tram times: `parseCrtm` + `mergeCrtm` (`src/gtfs.ts`): a line is covered only if CRTM has a row for it within [now - 1 min, now + 2 h]; each covered route shows its CRTM rows and drops the timetable rows they stand for (planned up to the route's last live time, plus the runs the live rows claim: closest pairs first, each run and live row once, nothing over 20 min apart (`claimedRuns`, `CLAIM_MAX_MS`), so CRTM's own 16:00:00 keeps the 16:00 run and a far estimate is an extra bus; `replacedByLive`); CRTM rows of the same route and destination under 60 s apart are one bus (`dedupeCrtm`, keeps the time with seconds); bus rows (`8_`/`9_` routes) on the whole minute are CRTM's timetable, not estimates (`isCrtmScheduled`, `scheduled`): they still replace their timetable run but are not `live` (no "en vivo"); one before a live row of the same route and destination is `unconfirmed` (`markUnconfirmed`: dimmed, tag "no confirmado"; CRTM lost that bus or the tracked one is it, late), keeping later timetable rows; other lines (absent, `SAEStatus` false, or only far-future rows) keep the timetable. No reliable live-vs-planned flag per time, so the status line says `en vivo · CRTM HH:MM` only when a shown departure is live (`freshText` in `src/gtfs.ts`); otherwise `<fuente> sin tiempos para esta parada · horario (HH:MM)`, or `solo horario` / `sin conexión · CRTM HH:MM`. CRTM codStop = stop id without `par_`.

## Rules

- All user-visible UI text is Spanish (Spain); code, comments and docs stay English. After adding or changing UI strings, run the `es-translator` agent (`.claude/agents/es-translator.md`, Haiku) to translate and check them.
- Never read, print or commit `.env` (it holds `NAP_TOKEN`).
- Wrap localStorage access in try/catch (use `loadJson` / `saveJson`). Keys are prefixed `madrid-transit:`.
- New parsing or maths logic gets an inline `console.assert` self-check.
- Interactive elements are real `<button>`s with `aria-*` state. Don't put `<div>`s inside buttons; use `<span>`.
